# ミッション・星のかけら 初回公開候補

現時点では未公開。main、本番Worker、D1、公開設定は変更していない。

## 初回範囲

- 1級6スロット。単語3形式・熟語2形式・大問9/11は選択式。
- 採点、学習保存、育成反映、達成時のかけら付与と残高表示。
- 各枠のかけらは同日・同アカウント・同級で1回。基本3枠達成で追加2個。合計最大19個/日。
- ガチャ・交換、2級、共通問題画面の途中回答復旧は含めない。
- 公開候補入口は今回必要なAPIのみ許可する。試作用のlearning/sync・companion/actionは公開対象外。通常画面の進化等は従来どおり。
- ミッション中は通常学習の自動保存を起動せず、開始前と完了後に既存save APIと同期する。
- 通常学習は引き続き既存save APIを使う。試作のlearning/syncの個体編集制限を通常学習へ適用しない。かけら残高とセット報酬履歴は別テーブルに保持する。

## 公開前に残る確認

1. 実ブラウザでPC/スマホの入力、音声、採点、保存、残高表示を確認する。
2. 実アカウントで開始前同期と終了後反映を確認する。現時点の検証はローカルSQLiteで発行した実形式セッションと公開候補Workerによるもの。Googleログイン画面の疎通確認ではない。
3. 下記の本番変更について承認を得る。検証中に本番へテスト報酬を付与しない。

## 承認後に適用する差分と順序

1. 本番D1のバックアップを取得。既存テーブルとmigration履歴を確認し、下記CREATE対象が未作成であることを確認する。
2. `cloud-worker/schema-drafts/economy-v1.sql`、次に `cloud-worker/schema-drafts/mission-rewards-v1.sql` を適用。既存学習テーブルの削除・初期化はしない。現在のファイルはDRAFT警告付きであり、本書は実行許可ではない。
3. Worker候補は `src/mission_release.js`。`wrangler.public.jsonc`のmainをこの値へ変更し、varsに `MISSION_RELEASE_ENABLED: "true"` を追加する。既存のOrigin、Google client ID、DB、rate limit、cronを保持する。
4. Worker正常稼働後、公開側 `cloud_config.js` に `missionsEnabled:true` を追加する。既存apiBaseを変更しない。ナビゲーションはこの値で `mission_play.html` に切り替わる。
5. 承認された差分だけをmainへ反映してPagesを公開する。ブランチ上の過去の試作を全て無条件に公開しない。

## 停止方法

- 不具合時はまず `missionsEnabled` をfalseへ戻して新規導線を止める。
- API停止が必要なら `MISSION_RELEASE_ENABLED` をfalseへ戻す。進行中の保存が拒否されるため利用者へ案内する。
- テーブル・残高・達成レシート・学習保存を削除しない。既存のログイン・save APIは従来入口へ委譲される。

## 既知の制限

- 問題画面で更新/タブ終了すると未保存の回答や再送状態を失う。通信エラー時は同じ画面で再試行する。
- 別端末との保存競合は自動統合せず、既存保存画面での確認を求める。
- 保存は段階的に進む。後段で失敗しても前段の学習保存等は確定していることがある。再試行時はレシートで重複加算を防ぐ。
- 出題時に個体がなければ育成加点なし。挑戦中の個体変更は停止する。
- 通常学習の保存内容は従来どおり端末から受け取る。今回の対応を、通常学習を含む全能力値の改ざん対策完了とは扱わない。
