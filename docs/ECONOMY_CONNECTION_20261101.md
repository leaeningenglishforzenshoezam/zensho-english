- `MISSION_RELEASE_ENABLED=true` と `ECONOMY_DRAW_ENABLED=true` の両方が必要。通常の `src/index.js` と本番設定は変更しない。

## 未完了・公開条件

### 追加：端末側の再開・保全基盤

- `goimon-items/cloud-draw.mjs`: 明示的に生成する通信クライアント。アカウント/API別に未完了の抽選要求を送信前保存し、再読み込み後も同じoperationIdで再送。結果も保存し、画面が表示済みと確認するまで保持する。
- 2タブの排他ロック、別アカウントへの切替、保存容量不足時の停止に対応。曖昧な通信エラーでは未完了記録を削除しない。
- `goimon-items/legacy-backup.mjs`: 1級・2級の旧所持品JSON（残高・装着内容を含む）を文字列のまま別キーへ退避。既存バックアップを上書きせず、元データは削除・書換えしない。これは正式残高への加算処理ではない。
- 認証済み通信クライアントから `/economy/draw` を呼べるようにした。ローカルSQLiteとの往復で、応答を失った後の再読み込みでも1回しか消費されないことを検証する。
- 公開画面は未切替。旧残高の扱い、級別/共通財布、確定拒否後のUI、装着データ同期が決まるまで本番フラグを有効化しない。

これはサーバー側の接続準備であり、正式ガチャの公開完了ではない。

1. `economy-v1.sql` 等はまだschema-drafts内。本番への適用手順・移行・ロールバック検証が必要。今回、通常migrationsへの追加はしない。
2. `goimon-items/shop.js` はまだ端末内抽選。UIの置換にはアカウント別の永続的な未完了操作保存、リロード後の同一ID再送、別タブ排他が必要。
3. 既存の端末内残高・所持品を自動でゼロにしない。一方、端末申告の値を無検証で正式残高へ加算しない。退避・移行方針が必要。
4. 共通財布はユーザー承認済み。開発フロントは `goimon_item_shared_v2` へ1級・2級の残高と所有数を合算し、級別の装着設定と元JSONを同じ1回の保存に含める。旧キーは削除しない。初回・ログインの受取済みは共通、ミッションの受取済みは級別に保持。保存前に上限・破損・旧画面からの更新を検査し、異常時は自動移行しない。
5. 10連保証の処理が未統一。端末版は最初の9枠にR以上がなければ最終枠を補正し、サーバー版は最終枠を常にR/SR（5:1）にする。今回どちらも確率ルールは変えていない。公開前に統一と表示の確認が必要。
6. ログインボーナス・初回ガチャ・各ミッション報酬の二重付与防止を正式APIへ接続する。
7. 装備・技の登録と所有数、重複交換の整合性を検証する。
8. `release_status.js` の authoritativeEconomy はfalseを維持。接続が終わるまで成功表示に変更しない。
9. 教師APIは別途教師承認とフラグ有効化が必要。
10. 本物のGoogleログイン・異なるブラウザでの復元は未検証。

### 共通化の接続範囲

ガチャ、装着、図鑑、クエスト第1章・第2章の編成、メニュー残高が共通所持品を参照する。装着による使用数は両級の現役・保存箱を合算して検査する。育成・学習キーは変更しない。

共通キーは端末内バックアップの対象に追加するが、通常のクラウド保存allowlistには追加しない。端末申告の資産を無検証で正式サーバー残高へ昇格させないためである。サーバー資産への移行・画面の抽選API切替・配備は引き続き未完了。本変更はGitHub開発ブランチのみで、main/本番API/Siteには未配備。
