# 公開接続と本人確認

## 実装済み

- `wrangler.release.jsonc` は既存のWorker名・D1・Origin・レート制限・定期処理を維持し、`mission_release.js` と必要な6フラグを選択する公開候補設定。
- 旧 `wrangler.public.jsonc` は変更しない。旧設定を再配備しても新機能が有効になるわけではない。
- `/health` は実際に接続した入口と全フラグが揃った場合のみ `missionRelease:1` と `authoritativeEconomy:true` を返す。これはDBマイグレーション成功や実アカウント検証の証明ではない。
- フロントは上記を確認後だけ新APIを使う。古いAPI／通信失敗では有効化しない。移行済みの所持品をローカル残高へ戻さない。
- ホーム・ハンバーガーメニュー・クエスト・ガチャのミッションリンクをログイン状態に合わせて切り替える。旧ミッションURLへの直接アクセスも新画面へ移動する。
- 復習からの戻り先はGitHub Pagesのプロジェクト配下・受験級を保持。

## 配備前提（まだ実行していない）

所有者のMacで最新版を取得し、リポジトリ先頭で `node scripts/release-preflight.cjs --remote-schema` を実行する。旧0011や部分適用で停止したら先に進まない。

新しいDBバックアップを取得して保存を確認した後、必要なマイグレーションを適用する。既存のバックアップを上書きしない。Cloudflareのログイン・バックアップ・本番配備は所有者が行う。トークンやDBバックアップをチャットに提出しない。

候補のビルド確認は `cloud-worker` で：

```bash
npx --no-install wrangler deploy --dry-run --config wrangler.release.jsonc
```

DB準備・バックアップ確認後の候補配備コマンドは：

```bash
npx --no-install wrangler deploy --config wrangler.release.jsonc --keep-vars
node ../scripts/check-deployed-api.cjs
```

これは現時点で実行済みという意味ではない。最後にfrontendを反映する。mainへの反映／公開サイトの更新はこの接続作業では行っていない。

## 所有者が行う最小限の実ログイン確認

テスト用アカウントを使う。生徒アカウントや普段の育成記録で初回確認しない。

1. 端末AでGoogleログイン。名前、相棒、学習記録を確認。初回移行は正しい記録がある端末で行う。
2. 単語ミッションを1回完了し、学習記録・育成・かけら残高を控える。保存完了後に再読み込みし一致を確認。
3. 端末B（または別ブラウザ）で同じアカウントにログインし、サーバーから復元。相棒・学習記録・残高・技装備・クエスト進行が一致するか確認。
4. 同じ日の同じミッションを再度達成しても、報酬が重複しないことを確認。

他の全問題を手で解き直す必要はない。異常があればデータ削除／初期化／古い記録の上書きをせず、画面のエラーと手順だけを報告する。
