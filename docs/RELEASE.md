# 初回公開の反映手順

状態（2026-10-11）: コードとローカル検証は完了。公開向けWorkerの反映とリモートD1の全マイグレーション適用を確認済み。運営方針は本人承認済み、ポリシー適用日は2026-10-11。mainへの反映と公開後の実Googleログイン確認はこの後に実施。

## 反映順

1. Google Cloudで既存のウェブ用OAuthクライアントの「承認済みのJavaScript生成元」に `https://leaeningenglishforzenshoezam.github.io` を追加する。パスや末尾のスラッシュは不要。localhostの設定は残す。
2. 最新の codex/google-cloud-save ブランチの cloud-worker で `npm ci`。必要なら `npx wrangler login`。
3. リモートD1をバックアップする。`npx wrangler d1 export goimon-cloud --remote --output=goimon-before-release.sql`。書き出し中は一時的にDBが利用できない。ファイルは公開しない。
4. `npm run db:remote`。既に適用済みの0001〜0003は維持し、未適用の0004と0005を適用する。失敗した場合は先へ進まない。
5. `npm run deploy:public`。同じ既存WorkerとDBを使用し、許可Originを公開サイトへ切り替える。以後はこのコマンドを使う。通常の `npm run deploy` はlocalhost用設定に戻るため使わない。この切替後はlocalhostからの同期は拒否される。
6. 公開Originを付けたhealthが200、無認証saveが401、外部Originが403であることを確認する。Google実ログインは公開フロントの反映後に確認する。
7. プライバシーポリシーの運営者情報の開示方法と運用準備を確定し、サーバー反映確認後に改定案表示を外して適用日を記入する。
8. 最新mainとの差分を確認し、検証ブランチをmainへマージする。GitHub Pagesの反映成功を確認する。
9. 公開サイトで実Googleログイン、初回プロフィール、アイコン、学習と自動保存、別端末の引き継ぎを確認する。Google画面でテストユーザーのみになっている場合は、一般利用前にOAuth公開設定も確認する。

## 注意

- 0004のCronは30日超の旧保存履歴と期限切れセッション等を整理する。最新の学習記録とプロフィールは削除しない。
- DBを作り直さず、localStorageを消さない。バックアップは非公開で保管し、不要になり次第、遅くとも30日以内に削除する。
- 問題時はフロント/Workerの前版へ戻す。追加DB列・テーブルは残し、DB全体の巻き戻しで新しい学習記録を消さない。
- 今回は新しい本番専用DBへ移行しない。既存の検証アカウントの記録も維持する。Worker名のstagingはURL維持のためそのまま。
